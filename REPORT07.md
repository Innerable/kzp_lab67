## 3. Порівняння словникової та об'єктної моделей

Словник: форма запису відома лише за домовленістю, перевірка живе в одному місці.

```python
record = {"full_name": "Іван", "group": "КІ-301", "year": 3, "average": 92.5}
record["average"] = 150  # ніхто не заперечує
record["avrage"]  # KeyError лише під час виконання
```

Об'єкт: інваріанти належать класу, поведінка поруч із даними.

```python
learner = Bachelor("Іван", "КІ-301", 3, 92.5)
learner.average = 150  # ValueError: average має бути числом 0-100
learner.rating()  # 92.5; для Master — average * 1.1
```

Висновок: об'єктна модель дає захист інваріантів після створення й поліморфізм замість
розгалужень. Ціна — більше коду (класи, setter-и, фабрика). Зовнішня поведінка при цьому
не змінилась: звіти двох лабораторних збігаються побайтово (див. розділ 8).

## 4. Модель
`Learner(full_name, group, year, average)` з `@property` та setter-валідацією: порожній текст
відхиляється; `year` — ціле в `YEAR_RANGE` типу; `average` — 0–100 включно, не NaN. Невдалий
setter не змінює попереднє значення. Спеціальні методи: `__str__`
(`Іван (КІ-301, курс 3, бал 92.50)`), `__repr__`, `__eq__` / `__hash__` (тип + ПІБ + група),
`__lt__` через `sort_key` (рейтинг за спаданням, потім ПІБ).

## 5. Dataclass
`GroupRating(group, count, mean_rating)` і `ReportSummary(...)` — `@dataclass(frozen=True)`.
Присвоєння дає `FrozenInstanceError`; рівність — за всіма полями; `dataclasses.replace`
створює змінену копію.

## 6. Підтипи та протокол
- `Bachelor`: курси 1–4, `WEIGHT = 1.0`; `Master`: курси 5–6, `WEIGHT = 1.1`.
- Спільна операція `rating() = average * WEIGHT`; підтипи відрізняються даними класу.
- `LearnerLike` — `Protocol` (`runtime_checkable`) з `full_name`, `group`, `year`, `average`, `rating()`.
- Тип обирається в одному місці — фабриці `create_learner` у `loader`; `analysis` типів не перевіряє.
  Тест `test_analysis_works_with_duck_typed_objects` передає об'єкт, що не є `Learner`.

## 7. Модулі й тестування

`models.py` (класи, dataclass, Protocol) — `loader.py` (CSV → об'єкти) — `analysis.py`
(через протокол) — `reporting.py` — `errors.py` — `cli.py`. `models` не читає файли,
`loader` не будує звіт, `analysis` не залежить від CLI.

## 12. Відповіді на контрольні питання
- **Чому `@dataclass`?** Генерує `__init__`, `__eq__`, `__repr__`; з `frozen=True` значення незмінне.
- **Як працює setter?** `obj.average = x` викликає метод із `@average.setter`, який перевіряє значення до збереження.
- **Як підтипи працюють зі спільною функцією?** Функція викликає `rating()`, а потрібну формулу
  вибирає сам об'єкт (поліморфізм), тому `if isinstance` не потрібен.
- **Навіщо `Protocol`?** Описує, що потрібно функції (поля й методи), не вимагаючи спадкування.
